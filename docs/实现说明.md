# 实现说明（开发者向）

本文补充 [README](../README.md) 之外的实现细节，便于后续维护和扩展。当前对应版本 1.1.0。

## 1. 分层

```
Views (XAML + code-behind, 只做 UI 编排)
   │  调用
Services (纯文件/文本逻辑，不依赖 UI，可单测)
   │  使用
Models (数据结构 / 列表行 ViewModel)
Helpers (HWND、选择器、对话框、资源管理器)
Localization (Lang + 字典 + Trans 附加属性 + 配置键名翻译)
```

设计原则：
- **Service 不弹窗、不读 UI**：所有 UI 交互（确认框、InfoBar）留在 Page；
- **IO 放到线程池**：`await Task.Run(...)` 包住读文件、解析、复制、写文件，避免大站点卡 UI；
- **状态集中**：`AppState.Current`（根目录 / 语言 / 主题 / 资源分组记忆）。

## 2. `_config.yml` 解析与写回（`Services/ConfigYamlService.cs`）

### 2.1 为什么不用 YAML 库

需求要求“原有注释、缩进、顺序尽量保持，只改用户改动的项”。通用 YAML 库序列化后会丢注释、重排格式，因此这里采用**行级缩进解析**：

- 按行扫描，维护“当前祖先栈”；
- 每行记录：`Key`、`Depth`、`Indent`、`LineIndex`、`Prefix`（值之前的原始文本）、`Suffix`（行尾注释）、`QuoteChar`、`RawValue`、`OriginalValue`、`EditingValue`；
- 写回时只需 `行 = Prefix + FormatScalar(EditingValue) + Suffix`，**其它行一个字节都不动**。

关键规则与 1.0 一致（`key:` 空值成组、块序列项、`- key: value` 序列映射、`|`/`>` 只读、行尾注释、引号风格等）。1.1 新增：

- `AppendTopLevelKey(configPath, key, value)`：站点图标没有 `favicon` 项时，在文件末尾追加一行（写前保留换行符 / BOM）。

### 2.2 值格式化（写回）

```
原值带引号 → 保留同类引号（' 内部转义为 ''）
否则：空 → 写空；布尔 → 小写裸写；数字 → 裸写；
      行内集合 → 原样；含 : # 特殊首字符或首尾空格 → 单引号包裹；其余裸写
```

### 2.3 写回流程（`Apply`）

1. 收集所有 `IsEditable && IsDirty` 的项；
2. 备份为 `<配置文件名>.easyhexo.bak`；
3. 复制原行数组，替换对应行，用原换行符拼接，保留原 BOM 写回；
4. 页面重新解析文件（保证界面与磁盘一致）。

## 3. 可视化编辑器（`Services/ConfigEditorMetadata.cs`）

按“完整键路径”（`pretty_urls.trailing_index`）决定控件类型，避免猜错语义：

| Kind | 控件 | 典型键 |
| --- | --- | --- |
| `Bool` | `ToggleSwitch`（写 true/false） | `titlecase`、`highlight.line_number`、`pretty_urls.trailing_index`… |
| `Choice` | `ComboBox`（可编辑，可选列表外值） | `language`、`timezone`、`date_format`、`time_format`、`permalink`、`syntax_highlighter`、`theme`、`deploy.type`… |
| `Number` | `NumberBox` | `per_page`、`index_generator.per_page`、`toc.max_depth`… |
| `Directory` | 文本框 + “浏览”选择文件夹 | `source_dir`、`public_dir`、`tag_dir`… |
| `Text` | 文本框 | 其它项 |

未收录的键如果值恰好是 `true`/`false`，也给开关；其余保持文本，避免误判。

**事件提交规则**（避免模板初始化 / 列表重建时误写）：

- 编辑器事件都先校验 `row.Kind`；
- 下拉框要求真正获得过焦点（`_focusedCombo`），数字框要求有焦点才提交；
- 文本框只在 `Kind` 为 Text/Directory 时提交；
- 这样展开/收起、撤回重建行时不会把 `language`、`per_page` 等清空。

**目录项**：选中的文件夹必须位于 Hexo 根目录内，转换成 `/` 分隔的相对路径（根目录本身写 `.`）。

## 4. 分区排序（`Services/ConfigLayoutService.cs`）

文件本身的顺序不会被修改（写回只替换值所在行），分区只影响界面展示：

`站点信息 → 网址与链接 → 目录 → 写作 → 代码高亮 → 首页与分页 → 分类与标签 → 元信息与时间格式 → 主题与扩展 → 部署 → 其它配置`

- 每个分区是 `ConfigSectionLayout`，分区标题行由 `ConfigRow.CreateSection` 生成，可整段收起；
- 分区内部按定义顺序排序，未在定义里出现的键排在该分区末尾（保持文件顺序）；
- 未识别的顶层键进入“其它配置”。

## 5. 高亮与撤销（`Views/ConfigEditorPage.xaml.cs`）

- `ConfigRow` 实现 `INotifyPropertyChanged`，`RefreshDirtyState()` 刷新 `IsDirty` / 背景 / 边框 / ● 标记；
- 撤销栈 `Stack<UndoStep>`：
  - 文本：`GotFocus` 记录旧值，`LostFocus` 或点“撤回”时算一步；
  - 开关 / 下拉 / 数字 / 目录选择：每次改动立即压栈；
  - “应用配置”或重新载入后清空；
- 撤回后重建可见行（输入内容保存在 `ConfigEntry.EditingValue`，不会丢）。

## 6. 主题与站点图标

### 6.1 主题（`Services/HexoThemeService.cs`）

- 扫描 `<Hexo根目录>/themes/` 的子文件夹，找 `_config.yml` / `_config.yaml`；
- 读取站点配置里的 `theme` 值作为当前主题；
- “一键切换”：把 `theme` 项设为所选主题 → 单行 `Apply` 写回 → 重新载入；其它未应用修改通过 `CapturePendingEdits / RestorePendingEdits` 保留；
- “编辑主题配置”：切到 `themes/<主题>/_config.yml`，使用同一套解析/写回逻辑，但**关闭键名翻译、关闭分区**，按文件缩进展开。

### 6.2 站点图标（`Services/FaviconService.cs`）

- 在当前配置里查找 `favicon`（任意层级、可编辑）；
- 解析：本机绝对路径 / `/x.png`（相对 `source`）/ `x.png`（依次尝试 `source`、根目录）；
- 更换：图片不在 `source` 内时复制到 `source\<文件名>`，再把配置值改为 `/文件名`；
- 配置里没有 `favicon` 时调用 `ConfigYamlService.AppendTopLevelKey` 追加；
- 预览：PNG/JPG/ICO 等用 `BitmapImage`，其它类型显示占位图标。

## 7. front-matter（`Services/FrontMatterService.cs`）

与 1.0 相同：首行 `---`、下一个 `---` 之间的 `title` / `date` / `tags`（行内数组或块序列），其它行原样保留；不符合结构时整个文件作为正文。

## 8. 发布流程（`Services/ArticlePublisher.cs`）

```
UI 校验（标题必填；目标存在则确认覆盖）
   ↓  Task.Run（后台线程）
AssetService.Process(..., selections)  按勾选复制资源并改写正文
FrontMatterService.Compose             title/date/tags + 原其它字段 + 正文
写入 source\_posts\<标题>.md（已发布文章写回原路径）
若来源是外部 .md 且不是目标文件 → 同时把结果写回该文件开头
   ↓ 回到 UI 线程
刷新文章列表 / 从“待发布”移除 / 自动切到下一篇 / InfoBar 汇报
```

`PublishRequest.AssetSelections` 是 `URL -> AssetSelection { Include, SourcePathOverride }`：

- `Include=false`：链接和文件都不动；
- `SourcePathOverride` 非空：用用户为“未识别项”选的本机文件复制；
- 未传 selections（null）时表示全部处理（兼容旧调用）。

## 9. 资源扫描与分组（`Services/AssetService.cs`）

- `Scan(body, articleDirectory)`：按顺序匹配 `![alt](url)` / `[text](url)`，保留“本机绝对路径”（`X:\`、`X:/`、UNC）和“相对文章目录的相对路径”（如 `..\Downloads\boot.img`，按 `articleDirectory` 解析），URL 去重；
- 分类：文件存在且是图片（`![]` 或图片扩展名）→ 图片；文件存在但非图片 → 文件；文件不存在 → **未识别项**（用户可“浏览”指定本机文件）；\n- 相对路径候选：非 `/`、`#`、`?` 开头、无 `://`、带扩展名且不是 html/php/md 等页面扩展名；
- 正则与 1.0 相同，仍然不处理 HTML `<img>`。

## 10. 本地化（`Localization/`）

- `Lang`：静态字典（`StringsZhCn` / `StringsEnUs`），`T(key)`；`SetLanguage` 后刷新界面；
- `Trans`：XAML 附加属性 `Text` / `Content` / `Header` / `Placeholder` / `ToolTip`，语言切换时对登记控件重新套用（弱引用，不阻止回收）；
- `ConfigKeyTranslator`：简体中文下按完整键路径翻译固定配置项键名，英文原名作为描述 / ToolTip；写回始终用英文键；
- 新增文案：两个字典同时加同一个 key（`XAML` 用 `l:Trans.Xxx="key"`，代码用 `Lang.T("key")`）；新增配置项译名改 `ConfigKeyTranslator.PathNames`。

## 11. 窗口、主题与自适应（`MainWindow` / `SettingsPage`）

- 最小尺寸：`OverlappedPresenter.PreferredMinimumWidth/Height = 1040/680`；
- 自适应侧栏：`PaneDisplayMode=Auto`，展开阈值 1260、紧凑阈值 800；`PaneOpened/PaneClosed/DisplayModeChanged` 控制 `PaneFooter` 中“当前 Hexo 根目录”的显隐；
- 主题：`AppState.Theme`（`system/light/dark`）→ `ThemeService.ToElementTheme` → 根 Grid `RequestedTheme`；`ContentDialog` 单独套用主题；切换后写入 `settings.json`。

## 12. 待发布文章与草稿（`Views/PublishPage.xaml.cs`）

- `Drafts: ObservableCollection<ImportDraft>`：导入的文件（含 `.txt` 临时文件）插入列表最上方；
- `ImportDraft.State: DraftState`（标题 / 日期 / 标签 / IsModified）：切换文章前 `SaveCurrentEditorState()` 把表单写回当前草稿或已发布文章的会话草稿字典；切回时恢复；
- 已发布文章的修改保存在 `_publishedDrafts`（路径 → 状态），本次会话内有效；
- 发布成功后从列表移除并更新计数，若还有草稿自动切到第一篇。

## 13. 线程与异常

- 文件读写、解析、复制、发布全部 `Task.Run`，UI 线程只做控件操作；
- 页面按钮在耗时操作期间禁用（发布页显示 `ProgressRing`）；
- 未处理异常写入 `%APPDATA%\EasyHexo\logs\easyhexo.log`，并 `Handled = true` 以免整个应用退出；
- 用户可恢复的错误通过 `InfoBar` 提示（成功/警告/错误三级）。

## 15. 运行页（对应 Hexo.bat）

- 位置：`Views/RunPage.xaml(.cs)`，侧栏“运行”；工作目录取当前站点根目录（不写死 `E:\Hexo`）。
- 命令：生成、清理、本地预览、部署、生成并部署、强制生成、监听生成、列出文章、查看版本、新建文章 / 页面、发布草稿，对应 bat 里的菜单项。
- 进程：`cmd.exe /d /c "chcp 65001>nul & <命令>"`，重定向 stdout / stderr 为 UTF-8；`OutputDataReceived` / `ErrorDataReceived` 回调里通过 `DispatcherQueue` 追加到输出框。
- 进度：执行时 `ProgressRing` 激活、状态栏显示“正在执行：命令”；运行期间命令按钮禁用、“停止”可用，结束后显示退出码。
- 停止：`CancellationTokenSource` + `Kill(entireProcessTree: true)`；离开页面时也会结束进程，避免遗留 `hexo server`。
- 输出：只读 `TextBox`（Consolas），实时追加；结束追加“完成（退出码 N）”或“已停止”。
- 新建文章 / 页面 / 发布草稿：参数去除引号，空值给出提示后再执行。

## 16. 配置页顶部布局与滚动保持

- 布局：`HeroCard`（基本信息：站点名称 / 作者 / 站点描述 / 关键词 / 语言 / 时区 + 右侧 112px 站点图标与“更换图标”）→ 主题行 → 分区列表；`site` 分区不再在列表中重复显示。
- 顶部控件与列表共享同一批 `ConfigEntry`：`FindEntry(path)` 按完整键路径查找，改动进入同一个撤销栈、同样的脏标记与统计。
- 滚动保持：`RebuildVisible` 前读取 `ScrollViewer.VerticalOffset`，重建后 `ChangeView` 恢复，并用 `DispatcherQueue` 再对齐一次；首次载入不保持。
- 列表回收防误写（重要）：`TextChanged` 只在控件有焦点时写回，`TextBox` 失焦时兜底比较提交；`ToggleSwitch.Toggled` 只在有焦点时提交；`NumberBox` 要求有焦点；`ComboBox` 要求真正获得过焦点。
- 基本信息脏标记：每个字段标题旁 `●` 按 `IsDirty` 显示 / 隐藏。

## 17. 用户数据目录与设置持久化

- 目录：`AppPaths.AppDataDir` = `%APPDATA%\EasyHexo`（不在软件目录），`settings.json` 与 `logs\` 都在这里；替换 / 升级软件文件夹不影响。
- 迁移：`AppPaths.MigrateLegacySettings()` 在启动最早时机执行——若 `%APPDATA%\EasyHexo\settings.json` 不存在，依次尝试复制 `%LOCALAPPDATA%\EasyHexo\settings.json`、软件目录下的 `settings.json`。
- 首次启动：`AppState.Initialize()` 读取设置后若文件仍不存在，会立即保存一份默认设置，保证用户配置目录被创建。
- 恢复站点：`Initialize()` 用保存的 `HexoRoot` 调 `HexoProject.TryCreate`，成功即赋给 `Project`，配置页启动后直接加载该站点。
- 保存站点：设置页 / 配置页选择目录都走 `AppState.TrySetRoot`，成功后写回 `HexoRoot` 并触发 `ProjectChanged`。
- 设置页布局：`ScrollViewer.HorizontalContentAlignment="Left"` + 内容 `HorizontalAlignment="Left"`，非最小宽度时也保持左对齐；语言 / 外观主题的说明文字已移除；站点目录按钮文案为“浏览”；新增“用户配置目录”卡片（显示路径 + 打开）。

## 18. 发布文章：分类管理

- 模型：`source\_posts` 下每个一级子文件夹是一个分类；直接放在 `_posts` 下的文章属于“未分类”。`ArticleService.LoadPosts` 递归扫描 `.md`，取相对路径第一段作为分类；`CategoryService.Scan` 额外把 settings.json 里记录过、当前为空的文件夹也当作分类（便于显示 / 删除）。没有 `.md` 且未被记录过的文件夹（多半是文章的资源目录）不当作分类。
- 创建 / 删除：`CategoryService.Create` 在 `_posts` 下建文件夹并把名称写入 `AppSettings.Categories`；`Delete` 只允许删除没有文章、也没有任何残留文件的分类。
- 调整分类：`CategoryService.MoveArticle` 把文章文件移动到 `_posts\<分类>\<文件名>`，同时把同名的资源目录（`_posts\<旧目录>\<文章名>\`）一起移动到新位置；目标已存在同名文章或资源目录时返回冲突，资源目录移动失败会回滚文章位置。
- 发布：`PublishRequest.Category` 参与 `ResolveTargetPath`，草稿发布时写入 `_posts\<分类>\<标题>.md`（空分类 = `_posts` 根目录）；已发布文章在界面改分类时立即调用 `MoveArticle`，并同步更新编辑器里的 `SourcePath` 与未发布草稿的键。
- 界面：左侧顶部是“分类筛选 + 新建分类 + 删除空分类”；每篇文章前有复选框，用于勾选多篇后选目标分类点“移动”；编辑区“分类”下拉框：草稿默认“不进行分类”，已发布文章显示当前分类或“未分类”；右侧底部“已选 N 篇 / 分类 / 移动”是批量操作条。
- 限制：更深的子文件夹不会单独作为分类（按第一段归属）；`front-matter` 的 `categories` 字段不会随文件夹自动改写。

## 19. 文章管理页（原发布文章）

- 侧栏名称与页面标题改为“文章管理”，功能不变。
- 批量调整分类条移到左侧“分类 / 新建分类 / 删除空分类”下方，默认隐藏；勾选文章后显示“已选 N 篇 + 目标分类 + 移动”。
- 修复勾选计数慢一拍的问题：`Checked / Unchecked` 事件先于双向绑定写回模型触发，处理函数里直接把 `CheckBox.IsChecked` 写入 `ArticleInfo.IsChecked`，再刷新计数。
- “全部标签”：`UpdateTagStats` 从 `_allPosts` 汇总标签与引用次数，按次数倒序填入 `TagFilterCombo`（首项“全部标签”）；选择后与分类过滤叠加。
- “从已有标签导入”：文章信息卡片里的 `Expander` 默认收起，展开后点击标签按钮调用 `AddTag` 加入当前文章（去重）。
## 20. 文本编辑器（TextEditorPage）

- 入口：配置编辑页顶部“转到文本编辑器”，通过 `Frame.Navigate(typeof(TextEditorPage), path)` 打开当前 `_config.yml` 或主题配置。
- `RichEditBox` + 左侧行号 `TextBlock`；行号随内部 `ScrollViewer.ViewChanged` 同步。
- Tab 键插入两个空格；`TextChanged` 时用正则对键名、字符串、注释重新着色（轻量 YAML 高亮），着色期间用 `_suppressHighlight` 防止递归。
- 保存：`Document.GetText` → 统一为 `\n` → 按原文件 CRLF / LF 与 BOM 写回，写前生成 `*.easyhexo.bak`；撤销 / 重做使用 `ITextDocument.Undo/Redo`。
- 返回：重新导航到一个新的配置页并清空 BackStack，避免 `GoBack` 恢复出空页面。
## 21. 图标、安装包与右键菜单

- 图标：`tools/make-icon.ps1` 用 System.Drawing 画 Hexo 风格六边形 + H + 齿轮，输出多尺寸 `Assets/EasyHexo.ico`；csproj `ApplicationIcon` 编译进 exe，`MainWindow` 调 `AppWindow.SetIcon` 设置窗口图标。
- 安装包：`tools/build-installer.ps1` 根据运行包目录生成 WiX v7 MSI（perUser，安装到 `%LOCALAPPDATA%\Programs\EasyHexo`），包含开始菜单快捷方式、ARP 卸载信息、App Paths 与 `.md` / `.txt` 右键菜单注册表项；卸载由 MSI 自带。
- 右键菜单服务：`ShellIntegrationService` 在 HKCU 写入 `SystemFileAssociations\.md/.txt\shell\EasyHexoPublish`，命令为 `"<exe>" --publish "%1"`；设置页“右键菜单”卡片可手动注册 / 移除。
- 启动参数：`App.ParsePublishArgument` 读取 `--publish <file>`，`MainWindow.OpenPublishFile` 选中“文章管理”并调用 `PublishPage.ImportFromPathAsync` 把文件加入待发布列表。
- 限制：Windows 11 经典菜单出现在“显示更多选项”；新式顶层菜单需要打包 COM 扩展，未实现。
## 22. 运行包目录归类

- `build-unpackaged.ps1` 打包前删除除 `zh-CN` / `zh-TW` / `en-us` 外的语言资源目录（这些目录必须留在程序根目录，WinUI 会按系统语言加载 MUI；移动到子目录会导致启动时布局 COMException）。
- 安装包与 zip 使用同一套目录结构。
